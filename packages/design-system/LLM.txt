## Regras do design system
- Import canônico único: import { ... } from '@leela/design-system' — nunca importe de caminhos internos (src/components/...).
- Dois temas via atributo data-theme no root: "brasa" (escuro, default) e "wine" (claro). O tema claro chamava-se "leela"; o valor de DOM "leela" NÃO existe mais nos CSS — só o ThemeProvider migra storage antigo. Troca de tema é responsabilidade do ThemeProvider (web) ou ThemeProviderRN (React Native).
- Zero valor cru: nenhuma cor (hex/rgb/hsl), espaçamento (px/rem), raio ou duração literal em style inline ou className arbitrária. Somente tokens var(--*) e classes de alias do preset (bg-card, text-foreground, ring-ring, etc.).
- Zero dark:: o DS não usa o modificador dark: do Tailwind. Tema é resolvido por tokens sob data-theme, nunca por classes condicionais de tema.
- Flat é o DEFAULT global dos form primitives (Input/Select/Textarea/SearchInput): sem borda em repouso, fill inset + focus ring. Opt-out via variant="bordered" — nunca reponha borda à mão.
- Governança §8 (PERMANENTE, leela-specs/04-engenharia/governanca-design.md): filtros, seleções ricas e calendários abrem painel do DS — use Combobox (Popover+Command) e DatePicker/DateRangePicker (react-day-picker em Popover). O <select> nativo (componente Select) só em formulário simples de baixa cardinalidade; <input type="date"> do SO é proibido.
- Cada componente tem um contrato LLM.txt no próprio diretório: props exatas, tokens consumidos, do/don't e exemplos válidos. O contrato do componente prevalece sobre qualquer memória de treinamento (shadcn stock, MUI, antd). Componentes marcados "(contrato pendente)" ainda não têm LLM.txt — leia o .tsx e o showroom antes de usar.

## Instrução para o modelo (colar no system prompt)
Antes de gerar qualquer tela com @leela/design-system, consulte o LLM.txt do componente que vai usar. Use apenas componentes, props e valores listados nos contratos. Nunca aplique cor, espaço, raio ou duração via literal; use somente tokens var(--*) do design system. Nunca use o modificador dark:; o tema é resolvido por data-theme (brasa | wine). Filtros, seleções ricas e calendários abrem painel do DS (Combobox/DatePicker — governança §8), nunca o listbox/calendário do SO. Não recrie primitivos que já existem (Input, Textarea, Radio, SearchInput, IconButton, Table, Drawer).
