## Regras do design system
- Import canônico único: import { ... } from '@leela/design-system' — nunca importe de caminhos internos (src/components/...).
- Dois temas via atributo data-theme no root: "brasa" e "leela". Troca de tema é responsabilidade do ThemeProvider (web) ou ThemeProviderRN (React Native).
- Zero valor cru: nenhuma cor (hex/rgb/hsl), espaçamento (px/rem), raio ou duração literal em style inline ou className arbitrária. Somente tokens var(--*) e classes de alias do preset (bg-card, text-foreground, ring-ring, etc.).
- Zero dark:: o DS não usa o modificador dark: do Tailwind. Tema é resolvido por tokens sob data-theme, nunca por classes condicionais de tema.
- Cada componente tem um contrato LLM.txt no próprio diretório: props exatas, tokens consumidos, do/don't e exemplos válidos. O contrato do componente prevalece sobre qualquer memória de treinamento (shadcn stock, MUI, antd).

## Instrução para o modelo (colar no system prompt)
Antes de gerar qualquer tela com @leela/design-system, consulte o LLM.txt do componente que vai usar. Use apenas componentes, props e valores listados nos contratos. Nunca aplique cor, espaço, raio ou duração via literal; use somente tokens var(--*) do design system. Nunca use o modificador dark:; o tema é resolvido por data-theme (brasa | leela).
